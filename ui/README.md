# Sendspin Image Server — Web UI

React + TypeScript + Vite front-end for the Sendspin image server. It talks to
the server's REST API (`/api/...`) and is served from `ui_dist/` by the Python
process in production, so there is no separate deployment step.

## Scripts

| Command | What it does |
| --- | --- |
| `npm run dev` | Vite dev server with HMR |
| `npm run build` | `tsc -b` then a production build into `dist/` |
| `npm run preview` | Serve the production build locally |
| `npm run lint` | Biome: lint + format check + import order |
| `npm run format` | Same as `lint`, but writes the safe fixes |

The dev server proxies API calls to the Python server — start that first
(`sendspin-image-server`), then `npm run dev`.

## Toolchain

- **Vite 8** with `@vitejs/plugin-react`
- **TypeScript 7**, project references (`tsconfig.app.json` for `src/`,
  `tsconfig.node.json` for `vite.config.ts`). `paths` maps `@/*` to `./src/*`;
  there is deliberately no `baseUrl`, which TypeScript 7 deprecates.
- **Tailwind CSS 4** via `@tailwindcss/vite`
- **Biome 2** for linting and formatting, replacing ESLint + Prettier

## Biome notes

`biome.json` is the single source of truth; there is no ESLint config.

- `src/components/ui/**` is excluded. Those files are generated by
  [shadcn/ui](https://ui.shadcn.com) (`npx shadcn add ...`) and get overwritten
  on regeneration, so formatting them only creates churn.
- Format-sensitive blocks opt out individually with `// biome-ignore format:`
  and a reason — see the aligned label table in `src/types.ts`.
- Biome has no equivalent of the React-Compiler-backed `react-hooks` rules
  (`set-state-in-effect` and friends). That class of bug is not caught
  automatically; if it becomes a problem, `eslint-plugin-react-hooks` can be run
  alongside Biome as a narrow second linter.

CI runs `npm ci`, `npm run lint`, and `npm run build` — see
`.github/workflows/ci.yml`.
